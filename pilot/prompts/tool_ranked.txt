6. You also have a profiling tool. Run the command `dc-profile` on its own (with no other commands in the same call) to profile the original `workload()` function against the current state of the repository. It returns a short ranked table of the repository functions that take the most self time in the workload, with file paths and line numbers, plus a one-line summary of time spent outside the repository. You may call `dc-profile` at most 4 times for this task.
